      KURUL · AI Agents

      Building Blocks

      All supported building blocks for DEHA ONE agents. Each building block represents a distinct operation, from AI model calls to conditional branching to data transformations.

      Building blocks are the components of an agent’s flow. Each building block performs a specific operation and passes its result on to the next step in the flow. All building blocks share a common structure in the configuration: 
      - id: "unique_node_id"
  type: "node_type"
  parameters:
    # Type-specific parameters
      The special identifiers __start__ and __end__ are reserved for the entry and exit points of the flow. They are used to connect building blocks but are never defined as building blocks themselves.

      AI Model Block (node_llm)

      Calls an AI model with the current conversation history and a system prompt. Optionally binds tools so the model can request tool calls.Parameters:
      ParameterTypeDefaultDescription
      modelstring(required)Model name or alias (e.g., gpt-4o, fast, claude-3-opus)
      providerstring(required)AI model provider
      temperaturefloat0.0Sampling temperature (0.0 = deterministic)
      max_tokensintegernullMaximum output tokens
      max_input_tokensinteger8192Maximum input context window for history trimming
      prompt_refstringnullKey in the prompts map to use as the system message
      bind_all_pipelinesbooleanfalseBind every user automation as a callable tool
      bind_pipelinesstring[]nullSelectively bind specific automation endpoints
      allowed_pipelinesstring[]nullWhitelist of automation names this model may call
      fallback_modelsstring[][]Ordered fallback models if the primary fails
      json_modebooleanfalseParse the model response as JSON
      _internal_onlybooleanfalseWhen true, the response is not sent to the user
      How it works:
      1. The message history is sanitized and trimmed to fit within max_input_tokens.
      2. The system prompt is rendered from the prompts map.
      3. The model is invoked. If the primary model fails, fallbacks are tried in order.
      4. If tool binding is enabled, the configured tools are attached to the model.
      5. The model is invoked and the response is added to the message history.
      6. If the response contains tool calls, the flow continues to a tool block.
      - id: "main_llm"
  type: "node_llm"
  parameters:
    model: "fast"
    temperature: 0.2
    max_tokens: 4096
    max_input_tokens: 12000
    prompt_ref: "system_main"
    bind_all_pipelines: true
      Use the fast model alias for cost-effective operations. The alias resolves to the best available model for your provider configuration. Or use smart for top-quality, cheap for cost-sensitive, reasoning for complex chain-of-thought.
      Automation-first: tools are exposed to agents as automation endpoints, not as raw integrations. When you set bind_all_pipelines: true, every automation endpoint defined for the user becomes a callable tool, with its own input/output schema, API key, rate limit, and timeout. Use bind_pipelines or allowed_pipelines to scope which automations a specific model call can invoke.

      Tool Block (node_tool)

      Executes tool calls generated by an AI model block. Routes each call to the right place and waits for results to arrive.Parameters:
      ParameterTypeDefaultDescription
      allowed_toolsstring[][]Tool whitelist. Empty list allows all tools.
      The tool block reads pending tool calls, determines the target for each call (REST API, sandboxed code, data query, etc.), dispatches the request, and waits. When the result arrives, the flow continues and the tool result is added to the message history.
      - id: "tool_executor"
  type: "node_tool"
  parameters:
    allowed_tools: []
      See Tools & Integrations for details on tool types and routing.

      Knowledge Block (node_knowledge)

      Performs a similarity search against the knowledge base for retrieval-augmented generation (RAG).Parameters:
      ParameterTypeDefaultDescription
      collectionstring"default"Search index name
      limitinteger3Maximum number of results (1—20)
      thresholdfloat0.7Minimum similarity score (0.0—1.0)
      query_sourcestring"last_message"Source for the query text
      filtersobjectnullAdditional metadata filters
      The block performs a semantic search and waits while results are retrieved. Search results are stored in context.rag_results as formatted text.
      - id: "search_kb"
  type: "node_knowledge"
  parameters:
    collection: "product_docs"
    limit: 5
    threshold: 0.75

      Approval Block (node_approval)

      Human-in-the-loop quality gate with two operating modes.Parameters:
      ParameterTypeDefaultDescription
      modestring"judge""judge" for automatic quality scoring, "always" for manual human review
      judge_modelstring"fast"Model used for automatic quality scoring
      judge_temperaturefloat0.0Scoring sampling temperature
      judge_promptstringnullCustom evaluation prompt
      approve_thresholdfloat0.7Score at or above this triggers approval
      handoff_thresholdfloat0.4Score below this triggers handoff to a human
      max_revisionsinteger2Maximum revision cycles before escalation (0—5)
      timeoutinteger300Approval timeout in seconds (30—3600)
      Judge mode: Automatic quality scoring evaluates the agent’s response and returns a score. Based on the score:
      • Below handoff_threshold, the conversation is handed off to a human agent.
      • Between thresholds, the response is sent back for revision (up to max_revisions times).
      • At or above approve_threshold, the response is approved and sent to the user.
      Always mode: The flow pauses and waits for a human staff member to approve, revise, or reject the response.
      - id: "quality_check"
  type: "node_approval"
  parameters:
    mode: "judge"
    approve_threshold: 0.7
    handoff_threshold: 0.4
    max_revisions: 2

      Condition Block (node_condition)

      Evaluates an expression and routes the flow to different branches based on the result.Parameters:
      ParameterTypeDefaultDescription
      modestring"expression"Evaluation mode
      expressionstring(required)Expression to evaluate
      branchesobject(required)Map of result values to target step IDs
      - id: "check_report_needed"
  type: "node_condition"
  parameters:
    mode: "expression"
    expression: "state.context.report_format != ''"
    branches:
      "true": "format_report"
      "false": "__end__"

      Router Block (node_router)

      Multi-branch routing based on a state value. Maps specific values to target blocks with a default fallback.Parameters:
      ParameterTypeDefaultDescription
      route_keystring(required)Dot-notation path to the routing value (e.g., context.detected_intent)
      routesobject(required)Map of values to target block IDs
      default_routestring"__end__"Fallback target if no value matches
      - id: "intent_router"
  type: "node_router"
  parameters:
    route_key: "context.detected_intent"
    routes:
      "shipping": "shipping_handler"
      "billing": "billing_handler"
      "technical": "tech_handler"
    default_route: "general_handler"

      ​
      Logic Block (node_logic)

      Evaluates a safe expression and stores the result in state. Useful for computed values, counters, and simple transformations.Parameters:
      ParameterTypeDefaultDescription
      expressionstringnullExpression to evaluate (e.g., retry_count + 1)
      output_keystring"logic_result"State key where the result is stored
      The expression runs in a sandboxed environment with access to all state variables and context values.
      - id: "increment_retries"
  type: "node_logic"
  parameters:
    expression: "retry_count + 1"
    output_key: "retry_count"
      Expressions support basic arithmetic, string operations, comparisons, and structured conditions (EQ, NEQ, GT, LT, CONTAINS, IN_LIST, REGEX, EXISTS). They cannot import modules or call arbitrary functions.

      Handover Block (node_handover)

      Transfers the conversation from the AI agent to a human staff member. After handover, the AI stops responding until the session is released.Parameters:
      ParameterTypeDefaultDescription
      handoff_messagestring"This conversation has been transferred to a representative."Message sent to the user
      assign_to_rolestring"agent"Staff role for assignment
      lock_sessionbooleantruePrevent AI responses after handover
      - id: "escalate"
  type: "node_handover"
  parameters:
    handoff_message: "I'm connecting you with a specialist."
    assign_to_role: "senior_agent"

      Fan-Out Block (node_fan_out)

      Sends messages to multiple targets without waiting for a reply. Does not pause the flow. Useful for triggering side effects such as archiving data or sending notifications.Parameters:
      ParameterTypeDefaultDescription
      targetsarray(required)List of target definitions
      targets[].event_typestring(required)Type of message to send
      targets[].payload_mappingobject{}Map of output keys to state paths
      - id: "notify_all"
  type: "node_fan_out"
  parameters:
    targets:
      - event_type: "data.archive"
        payload_mapping:
          entity_name: "literal:customer_interaction"
          data: "context.interaction_summary"

      Set Variable Block (node_set)

      Updates a state variable with a static value, a dynamically extracted value, or a computed expression.Parameters:
      ParameterTypeDefaultDescription
      variablestring(required)Target variable name in state
      valueanynullStatic value to assign
      fromstringnullDot-notation path for dynamic extraction (e.g., context.messages[-1].content)
      expressionstringnullSafe expression to evaluate
      operationstring"set"Operation: set, increment, append
      validate_schemastringnullEntity schema name for validation
      Value resolution priority: from > expression > value.
      # Static value
- id: "set_priority"
  type: "node_set"
  parameters:
    variable: "escalation_level"
    value: "high"

# Dynamic extraction from last AI model response
- id: "capture_summary"
  type: "node_set"
  parameters:
    variable: "executive_summary"
    from: "context.messages[-1].content"

      Transform Block (node_transform)

      Performs data transformation operations on state values.Parameters:
      ParameterTypeDefaultDescription
      operationstring(required)Operation type (see table below)
      OperationDescriptionKey Parameters
      extractExtract a single field from context or inputinput_key, output_key
      mapMulti-field mapping with dot-notation referencesmapping: {key: "context.path"}
      templateTemplate renderingtemplate, output_key
      filterFilter a list by conditionsource, condition, output_key
      mergeMerge multiple dicts from statesources, output_key
      Filter operators: ==, !=, in, contains.
      # Extract a field
- id: "extract_intent"
  type: "node_transform"
  parameters:
    operation: "extract"
    input_key: "intent"
    output_key: "detected_intent"

# Map multiple fields
- id: "build_payload"
  type: "node_transform"
  parameters:
    operation: "map"
    mapping:
      customer_name: "context.user_profile.name"
      order_id: "context.order_details.id"

      AI Transform Block (node_llm_transform)

      Like node_transform, but uses an AI model to perform the transformation. Best for tasks where rules-based mapping is insufficient, fuzzy classification, sentiment, extraction, summarization, language detection.Parameters:
      ParameterTypeDefaultDescription
      modelstring"fast"Model alias or specific model
      promptstring(required)Instruction for the model
      input_keysstring[](required)Which state keys to feed into the prompt
      output_keystring(required)Where to store the result
      schemaobjectnullJSON schema; if set, output is validated
      - id: "classify_intent"
  type: "node_llm_transform"
  parameters:
    model: "fast"
    prompt: "Classify the customer's intent as one of: shipping, billing, technical, sales, other."
    input_keys: ["context.messages[-1].content"]
    output_key: "detected_intent"
    schema:
      type: string
      enum: [shipping, billing, technical, sales, other]

      PII Scrub Block (node_pii_scrub)

      Detects and anonymizes PII (personal information) in state values. Useful for protecting user data before it is logged, archived, or sent to a downstream service.Parameters:
      ParameterTypeDefaultDescription
      input_keystring(required)State path containing the text to scrub
      output_keystring(required)Where to store the scrubbed text
      operationstring"redact"One of redact, mask, hash, replace, encrypt
      entitiesstring[]autoSpecific PII types to look for, or auto for all
      See Privacy & PII for the full list of detected entities.
      - id: "scrub_before_archive"
  type: "node_pii_scrub"
  parameters:
    input_key: "context.user_message"
    output_key: "context.user_message_safe"
    operation: "mask"

      Automation Block (node_pipeline)

      Invokes an automation as a tool from within an agent’s flow. This is the cornerstone of the automation-first approach, heavy lifting (data extracts, ML, optimization, scraping) lives in automations, while agents call them like tools.Parameters:
      ParameterTypeDefaultDescription
      pipeline_namestring(required)Name of the automation endpoint to call
      input_mappingobject{}Map state values to automation inputs
      output_keystringpipeline_resultWhere to store the result
      syncbooleantrueWait for completion; false returns immediately with an invocation ID
      timeoutinteger120Max seconds to wait when sync: true
      - id: "run_forecast"
  type: "node_pipeline"
  parameters:
    pipeline_name: "weekly_demand_forecast"
    input_mapping:
      horizon_days: "context.requested_horizon"
    output_key: "forecast_result"
    timeout: 60

      Orchestrator Block (node_orchestrator)

      Delegates a sub-task to another agent. The flow pauses while the sub-agent runs and resumes when it returns. Used to build hierarchical agent systems, a generalist routes to specialists who can route to sub-specialists, with no depth limit.Parameters:
      ParameterTypeDefaultDescription
      agent_namestring(required)Target sub-agent
      input_mappingobject{}Map state to sub-agent input
      output_keystringsub_resultWhere to store the sub-agent’s reply
      preserve_historybooleanfalsePass full conversation context to the sub-agent
      See Multi-Agent Orchestration for patterns and examples.
      - id: "billing_specialist"
  type: "node_orchestrator"
  parameters:
    agent_name: "billing_agent"
    input_mapping:
      question: "context.messages[-1].content"
      customer_id: "context.user_profile.id"
    output_key: "billing_reply"

      DEHA Block (node_deha)

      Embed DEHA inside your agent’s flow. Useful for agents that need to inspect or modify platform configuration on the fly (“create me a new connector,” “list my automations,” “what does this agent cost?”).Parameters:
      ParameterTypeDefaultDescription
      modestring"chat"chat, execute, inventory, or insights
      input_mappingobject{}Map state to DEHA input
      output_keystringdeha_resultWhere to store DEHA’s response
      dry_runbooleantrueFor execute mode, skip applying changes
      - id: "ask_deha"
  type: "node_deha"
  parameters:
    mode: "inventory"
    input_mapping:
      question: "context.messages[-1].content"
    output_key: "platform_summary"

      Error Recovery Block (node_error_recovery)

      Catches unhandled errors from earlier building blocks and routes the flow to a recovery path. Use this to keep agents responsive when tools fail or model calls time out.Parameters:
      ParameterTypeDefaultDescription
      recovery_messagestring"Sorry, something went wrong. A team member will follow up."Fallback reply to the user
      notifyobjectnullOptional notification target (Slack channel, email)
      escalate_to_rolestringnullIf set, hand off to this human role
      - id: "on_error"
  type: "node_error_recovery"
  parameters:
    recovery_message: "I'm having trouble looking that up. A team member will reach out shortly."
    escalate_to_role: "senior_agent"
    notify:
      channel: slack
      target: "#oncall"
