DEHA ONE supports two ways to authenticate: **single sign-on (SSO) sessions** for interactive dashboard use, and **API keys** for programmatic access from your own systems.

## Single sign-on (SSO)

The dashboard and web applications sign you in through your identity provider using open standards (OIDC). Your session token is included as a bearer token, and its signature, audience, and issuer are verified on every request.

```bash
Authorization: Bearer <session-token>
```

Sessions are best for interactive, browser-based use. For server-to-server calls, use an API key instead.

### Roles

Each member of your workspace has a role that controls what they can do:

| Role | Permissions |
|------|------------|
| `owner` | Full access, including billing and team management |
| `admin` | Team management, deployment, all operations |
| `supervisor` | Read/write configuration, manage agents |
| `agent` | Operational access, limited configuration read |
| `viewer` | Read-only access |

See [Roles and Permissions](/security/roles-and-permissions) for the full breakdown.

## API key authentication

API keys are used for programmatic access from external systems such as automation tools, custom backends, and CI/CD pipelines. Include the key as a bearer token:

```bash
Authorization: Bearer <your-api-key>
```

You create and manage API keys from the dashboard. Keys can be scoped to your whole workspace, to a single agent, or to a single pipeline. See [API Keys](/security/api-keys).

### Example -- call your agent

<CodeGroup>
```bash cURL
curl -X POST "https://api.deha.one/api/v1/agent/acme_corp/support_agent/invoke" \
  -H "Authorization: Bearer <your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"message": "What is the status of order 12345?"}'
```

```python Python
import httpx

client = httpx.Client(
    base_url="https://api.deha.one",
    headers={"Authorization": "Bearer <your-api-key>"}
)
response = client.post(
    "/api/v1/agent/acme_corp/support_agent/invoke",
    json={"message": "What is the status of order 12345?"}
)
```

```javascript Node.js
const response = await fetch(
  "https://api.deha.one/api/v1/agent/acme_corp/support_agent/invoke",
  {
    method: "POST",
    headers: {
      "Authorization": "Bearer <your-api-key>",
      "Content-Type": "application/json"
    },
    body: JSON.stringify({ message: "What is the status of order 12345?" })
  }
);
```
</CodeGroup>

### Rate limits

Each API key has a configurable rate limit (default: 60 requests per minute), set when the key is created and adjustable by administrators.

### Security best practices

<Warning>
API keys grant access to your workspace resources. Treat them like passwords.
</Warning>

- Store API keys in environment variables or a secret manager -- never in source code.
- Rotate keys regularly from the dashboard.
- Restrict each key's access to specific IP addresses when possible.
- Each key is shown in full only once, at creation. If lost, rotate it to generate a new one.

## IP allow-lists

You can optionally restrict access to specific IP addresses. When an allow-list is active, requests from any other address are rejected with `403 Forbidden`, regardless of valid authentication. Both exact addresses and ranges are supported, managed from the dashboard.

## Error responses

| Status | Description |
|--------|-------------|
| `401` | Missing or invalid authentication token / key |
| `403` | Valid credentials but insufficient permissions, workspace mismatch, or IP not allow-listed |
